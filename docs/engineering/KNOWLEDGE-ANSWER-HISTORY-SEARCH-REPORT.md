# 已保存问答的本地查找

日期：2026-11-11。基线 `933279c`。本轮第三个实质模块。

## 用户流程

此前问答历史只能按时间翻页。现在知识页与工作区查找／准备会话参考都提供独立的问答关键词入口，按保存的问题全文、原检索词和回答正文作区分大小写的连续原文匹配。支持 1–128 个 Unicode 字符，空白和大小写原样保留，`%`／`_` 是普通文字；不使用 SQL LIKE、内部提示词、引用元数据或模型检索。结果沿原时间倒序，每页 20 条；打开后读取原问题、固定版本回答与引用，沿原有选段／回查／插入草稿流程使用。未提交的问题和会话草稿不因查找改变，发送仍需用户明确操作。

分页使用已经提交的关键词，编辑搜索框不改变当前结果条件。空结果、失败、查询回显或页码不匹配、session 迟到回执均不展示为当前结果。列表变化导致超出末页时有界返回仍有效页，仍保持原查询；不回退全库搜索或自动生成。新查询及刷新收起旧阅读，准备区已明确选择的参考保留，并在插入前重新核对。

## 实现合同

- Runtime 新增 Native-only `GET /api/v1/knowledge/answer/tasks/search`。使用现有私有历史连接，最多扫描既定 1000 条，按反序列化的 `KnowledgeAnswer.answer` 匹配回答，不在 JSON 序列化字符串上匹配。无新表、迁移、派生索引或外部依赖。当前页和总数从同一同步扫描得到，不宣称跨页一致快照。
- C# 与 React Bridge 新增只读 `knowledge.answerHistorySearch`，严格校验 `query + results`、页码、总数、摘要身份和容量。与旧列表共用原生 `HistoryGeneration / HistoryPage`：只授予本页结果，不为可编辑 ID 放宽授权。旧列表合同保持兼容。
- 阅读结果复用本轮已完成的准确 ID 列表定位，因此不会因其他参考读取改变授权页而改用错误记录。确认删除历史时也先重新取得该条记录的当前读取资格，然后仅删除确认的原 ID，刷新时保留查找条件。
- 搜索摘要保留原来的问题、日期与状态；正文命中位置需打开原回答阅读，本轮没有添加片段排名或语义检索。
