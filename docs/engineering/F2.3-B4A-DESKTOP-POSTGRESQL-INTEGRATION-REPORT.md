返回当前配置选择的 SQLite/PostgreSQL 引擎、连接字段是否完整、实际连接结果、Workspace V1/V2 与 Knowledge schema 状态、
Finance 开关／元数据检查状态、最近检查时间和固定安全错误码。已准备候选不等于当前已启用。
Workspace 数据源复用原配置工厂的显式 loopback URL／端口／数据库与无 URL options 合同；
拒绝以 postgres 作为应用角色，连接后拒绝高权限角色。连接与查询有超时，仅在只读事务中查角色／migration history／表结构。

不执行 Finance Flyway、不读取账户金额或用户记录。这一 Finance 正向配置分支本轮未做真实数据库验收。

用户名、密码、SQL、私有目录或 cluster identity。Knowledge READY 仅指数据库结构，不代表文件生命周期／索引／正式切换验收。

## 6. PostgreSQL 配置路径与当前缺口

本轮复用原字段，不新增明文配置文件或 React 密码表单：

| 字段 | 用途 |
| --- | --- |
| workspace.persistence.backend | 当前引擎，默认 sqlite；不由状态查询改变 |
| workspace.persistence.postgresql.url / username / password | 已有受控外部配置，仅在 Runtime 内读取；URL 必须显式 loopback 且无选项 |
| workspace.finance.enabled | 默认 false，不由页面启用 |
| workspace.finance.datasource.* | 已有 Finance 独立数据源配置，只有模块启用后才使用 |

**正式 Windows 桌面凭据注入入口尚未交付。** 源码确认 WindowsNativeGate 拒绝 SPRING_/WORKSPACE_ 等环境覆盖、
workspace.* 系统属性和额外启动参数；现有合法 Profile 参数只有固定端口／token／data／model-state。
本轮没有修改其准入合同、制作旁路配置加载器或向启动参数放密码。
真实连接验证直接实例化独立状态服务并注入本轮隔离配置，没有运行或伪装 Windows 受信 main。
当前合法正式启动仍受 Gate 限制；选用 PostgreSQL 但配置不完整时，原 Store 启动的 fail-closed 行为保持，
不能保证 Runtime 已启动到可查询状态，也不会自动退回 SQLite。
