# 工作区查找与原文阅读

2026-11-10，基线 `4cb8973`，产品提交 `9cb7e31`。**完成第三个独立实用模块：从当前工作区页面主动查找已保存的记忆、对话消息和资料，分组查看结果并阅读准确上下文，关闭后继续原草稿。** 没有将前两项来源功能拆分计数。

## 缺口、价值与完成判据

原 V1 目标强调统一 Windows Workspace、显式 Memory／持久 Conversation／独立 Knowledge，以及子系统降级，见 [原目标](../history/2026-10-28/V1-ROADMAP.md)。检查 App 导航及三个领域页面后确认：各自已有查询，但没有跨页面查找入口；用户必须先决定资料属于哪个领域，再离开正在编辑的页面。

本模块的输入是用户明确提交的 1–100 字关键词及记忆／对话状态范围。输出分别为记忆元数据、命中消息与资料片段，以及按需读取的原文。完成判据：一次入口可查三个领域；单组失败不抹除其他组；记忆和消息可以分页；打开结果核对准确身份／版本；关闭和会话变化不混入迟到回执；普通查看不更改当前草稿或模型上下文。上述判据已在合成前端流程中验证，桌面验收层级另列。

## 用户流程与实现

- App 侧栏新增“查找工作区”。原生 HTML dialog 显示查询表单和结果；底层各页面继续挂载，普通打开／关闭不切换路由或触发离页丢弃。支持 Escape 对应的 cancel 事件，恢复入口焦点；点击结果将焦点送到阅读区，收起预览回到命中按钮。
- 只在提交时并行调用既有 `memory.list`、`conversations.search`、`knowledge.search`。各组独立展示加载、结果或失败，并提供组内重试。输入法组合期间不提交；请求未完成时防止重复提交。查找条件和结果仅存在于当前面板，不写 URL、存储或日志。
- 记忆选择活动／归档范围，每页 20 条；对话选择全部／活动／归档，每页 10 条消息。两者沿用连续原文匹配；资料沿用现有词法检索，查询活动资料当前可用版本，最多 10 个片段。界面标明已提交的关键词与各组范围，不合并排名或虚构跨领域总数。
- 记忆预览复用 `MemoryPreview`，核对返回 revision／状态，变更后提示重新查找。对话按命中 sequence 算出精确历史页，再核对 turn ID、sequence、message ID、role 和关键词仍存在；展示该轮已保存的用户消息和助手回复，不跳到最新一轮。
- 资料先取同 ID 详情，核对命中源版本仍存在，再读取该版本的准确偏移。当前版本已变化时明确显示所读旧版；版本缺失不回退。上下文沿同一版本阅读前后文／返回命中位置，返回栈最多 32 个偏移。内容和高亮均为 React 文本，不执行 HTML、Markdown 或链接。
- 搜索和阅读生命周期绑定面板及 Bridge 会话。关闭、重查或会话变化使旧结果失效；旧资料详情迟到后不会继续发起预览。既有只读请求可能完成，但不会写入新面板。App 会话重置继续沿用原来的草稿生命周期，不宣称跨会话保留旧草稿。

代码入口为 `WorkspaceSearchDialog.tsx`、`WorkspaceSearchReaders.tsx`、App 和局部样式。复用预览时给 Memory DOM ID 添加可选前缀，Knowledge 范围说明改用 React `useId`，避免面板和底层已打开的预览重复 ID；既有调用仍兼容。

没有新 Native／Runtime API、schema、搜索索引、权限或数据迁移，没有自动重建索引、模型调用、Memory 写入／选择、对话发送或隐式保存。资料出处仍只是可编辑定位线索，未变成受信关联或已验证事实。
