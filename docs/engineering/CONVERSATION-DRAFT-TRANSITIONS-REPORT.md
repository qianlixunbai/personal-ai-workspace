## 已完成行为

### 网页会话：成功打开后才替换编辑内容

此前点击其他会话、再次点击当前会话、新建会话或切换归档筛选都会直接重置消息草稿；只有历史搜索提供单独保护，未保存的重命名标题也未受到保护。

现在这些入口复用同一默认取消的确认框，识别未发送消息和未保存标题。点击当前会话不改变内容；鼠标及方向键切换列表均经过确认。读取目标的最新页及搜索命中核验成功后才切换，读取失败或失效命中保留原会话、草稿和标题。切换期间编辑器不可修改，会话轮换／离页使确认和迟到响应失效。

成功切换仍清除双方显式 Memory 使用范围和本次临时接纳回执；没有自动发送、取消任务或恢复历史接纳信息。若清除范围失败，保留草稿并取消切换，同时移除不能再确认可用的前端选择。新建成功而打开失败时明确说明新会话已经存在，提示刷新后打开，避免把读取失败误认为需要再次新建。删除确认说明草稿也会丢弃；已经打开的重命名编辑器不会被重复点击覆盖。

### 原生会话：草稿继续绑定原会话

此前下拉框切换会话时保留原输入文本，可能把它带入另一上下文；目标读取失败时下拉框已经变化，详情却仍为旧会话。刷新也可能在当前会话不见后自动选中列表第一项。

现在切换／新建前有明确的草稿确认。目标完整读取成功才同时替换下拉选择、详情、分页状态与当前待处理任务，随后清空属于旧会话的草稿和 Memory 选择；取消或读取失败保持原内容。重复选择当前会话不触发确认，不丢草稿。刷新仍按当前 ID 读取，不静默退到另一条记录；同一会话刷新保留输入。新建已完成而读取失败会显示可核对的“已创建”提示。分页读取失败不会提前移动页码。

两个修复都只调整客户端交互，复用现有 API／校验，没有新依赖、数据库 schema、模型调用、自动重放、自动保存或恢复权限。草稿仍是窗口内临时内容，不保证关闭应用或会话身份轮换后的恢复。
