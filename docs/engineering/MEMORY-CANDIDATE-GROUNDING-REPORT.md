## 本轮改动

- 提示要求 title 和 content 都沿用实际来源语言，不能跟随英文指令或示例语言翻译；正文必须保留项目、时间、条件、否定和新旧值关系，不能只把这些信息留在标题里。
- 要求先从当前 text 复制一段连续 evidence，逐字保留标点与空白，不改写、翻译、拼接或规范化。明确只有 content 可以摘要，无法给出忠实候选和准确摘录时返回无候选。加入一个有新旧时间关系的中文示例，并说明示例不是当前来源。
- 保留原有 `source.includes(evidence)` 的严格验证，没有补字、翻译、Unicode 规范化、模糊匹配或自动重试。错误区分格式、摘录和明显文字体系偏离，以便界面说明拒绝原因；原草稿和原始输出保留，只能由用户手动整理后显式保存。
- 新增一项保守校验：来源至少有 8 个字母且全部属于 Han 或全部属于 Latin 时，若候选标题或正文也至少有 8 个字母、全部属于另一类，则拒绝。标点、数字不计作字母。这只是明显整段文字体系变化的拦截，**不是通用语言检测**：混合文字、短文本、日文等其他体系、法语到英语等同体系翻译，以及遗漏范围、错误否定和归属都仍需内容审阅。相关局限也有离线用例，防止把规则扩大宣传为语义保证。
- 审阅提示明确要求核对语言、项目／时间范围、否定关系和来源归属。已经进入候选编辑器后的用户修改仍由现有 Memory 输入限制管理；不会将用户手动编辑误当成模型输出再自动翻译或替换。
- 提示更长，仍使用原有 3000 UTF-16／5632 UTF-8 输入预算。可接受的来源长度随编码和转义变化，超限仍提示手动精简，不截断正文或扩大模型预算。本轮验证 600 个汉字的合成来源仍能提交。
- 下一轮 opt-in 真实模型脚本会保留 `rejectionCode`、`contractPassed`、整组 `checksPassed`，并明确 `semanticReview: NOT_PERFORMED`；机器合同通过不等于内容审阅通过。原先的真实失败证据未重写。
