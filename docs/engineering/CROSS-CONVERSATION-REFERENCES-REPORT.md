# 跨会话历史参考准备

2026-11-10，基线 `a6e71ba8368d7631ce81e2448c58e71542768d53`。本会话第三个完整用户模块：在当前问题中主动查找旧对话，选择历史消息原文，审阅带精确出处的参考，重新核对来源后插入当前会话草稿，再由用户手动发送。

## 原缺口与完成流程

已有“准备会话参考”支持资料和记忆，但对话搜索结果仅能阅读，不能加入参考。用户需要离开准备流程，手工复制旧消息并补充出处，容易遗漏选取范围或混入另一条消息。

- 准备参考时，打开命中的历史消息即可选择片段，或明确加入整条命中消息。只允许复制该消息；同轮的另一条消息仍仅供阅读，历史 Memory 选择和上下文权限不随文字复制。
- 待审阅参考保留来源标题、会话 ID、轮次 ID／序号、消息 ID／角色及精确偏移。展示完整原文，支持去重、回查、移除，沿用最多四项参考与完整消息长度限制；超长不会截断。
- 待选参考的回查按精确位置读取并高亮所选范围，不依赖后来改变的搜索词。缺失身份、Pending 轮次、消息内容或名称变化会保持失败，不能换消息／最新轮次补足。
- 插入前逐项重新读取并核对来源。任意一项不符则整体不插入；全部通过后仍须由原会话的既有 `apply` 检查目标会话、草稿快照和生命周期，再一次替换草稿。
- 搜索／阅读／加入参考不改变目标草稿。插入也不发送问题、不创建记忆、不选入 Memory、不调用模型；只有以后用户明确发送才进入既有 Runtime 流程。
- 关闭、取消、目标草稿后来被编辑或 Bridge 会话变化后，迟到核对结果不能覆盖当前草稿。普通关闭保留目标草稿；Bridge 会话重建继续使用原有清空规则，不宣称跨会话保留。

## 代码边界

新增 `ConversationReferenceMessage.tsx` 负责已打开的准确消息的纯文本选区。`WorkspaceSearchReaders.tsx` 增加待选参考的精确回查模式；普通工作区查找仍只读，只有会话参考准备模式显示加入按钮。再次选择同一条结果也会建立新的阅读实例，避免把先前预览当作新回查。

`conversationReferences.ts` 增加历史消息参考类型、定位文字及核对分支；复用上一模块的只读 `readConversationSource`，未修改该辅助模块。`WorkspaceSearchDialog.tsx` 将历史消息接入已有审阅／去重／删除／完整消息预览及目标草稿确认流程。没有新增 Runtime／Native API、schema、搜索索引、模型流程、持久化协议或权限。

参考只是普通消息中的文字副本，出处可编辑，不构成受信引用或事实验证。JSON 标题和正文均作为 React 文本展示，脚本／HTML 不执行；历史助手回复仍需核实。来源后来修改或删除不会自动更新已经插入的文字。
