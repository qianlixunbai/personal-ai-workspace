## 2. 成熟方案选择及依赖

评估了 [age 官方 passphrase 模式](https://github.com/FiloSottile/age#passphrases)：标准方案适合跨设备，
但本机没有 age/Go 工具，本轮不增加原生工具部署和终端口令桥接，也不通过环境变量/口令参数绕过其交互合同。

选择现有 Java 技术栈中的 **Bouncy Castle 1.86 标准 OpenPGP RFC 9580**：
`org.bouncycastle:bcpg-jdk18on:1.86`，从 Maven Central 获取；实际测试 classpath 确认 bcpg、bcprov、bcutil 均为 1.86。
纯 Java，在本机 Windows x64 / Java 21 实际运行；没有添加长期进程、全局 JCE provider 或自行实现加密协议。
版本在本轮通过 [Maven Central metadata](https://repo.maven.apache.org/maven2/org/bouncycastle/bcpg-jdk18on/maven-metadata.xml) 核实。

使用 [BC 官方 RFC 9580 实现](https://github.com/bcgit/bc-java/tree/r1rv86/pg) 提供的：

- SKESK v6 + SEIPD v2，AES-256-GCM；64 KiB AEAD chunk，逐 chunk 标签及末尾消息认证由库完成。
- Argon2id（RFC 9106 memory-constrained profile）：64 MiB、3 passes、4 lanes；随机 16-byte KDF salt。
  使用库的 [memoryConstrainedParameters](https://github.com/bcgit/bc-java/blob/r1rv86/pg/src/main/java/org/bouncycastle/bcpg/S2K.java)，未降低演示强度。
- 随机 session key、IV、salt 和标准 key wrapping 均由库及 SecureRandom 处理；没有固定密钥或 salt。
- 解密先在最多 64 KiB packet header 中检查版本、算法、精确 KDF 成本及 chunk profile，再进入 KDF，
  不允许未认证输入请求任意内存/CPU成本。

跨设备需 Java 21、这些依赖和维护类；实际数据库恢复还需目标电脑的 PostgreSQL 17 工具及独立目标配置。
解密本身不需要 PostgreSQL 服务。工具安装位置从认证后读取的目标配置 `tools` 获取，不恢复原设备绝对路径。
未实测其他 OpenPGP 客户端；不承诺旧 RFC 4880/GPG 实现能够解密该 RFC 9580 / Argon2 profile。
依赖按 Maven 打包合同引入，但本轮未运行 Windows packaging，最终分发仍需核对入包与依赖版本维护。

## 3. 加密容器及完成合同

整套 B3 文件流式写入 ZIP，再直接进入标准 OpenPGP literal data 加密流，不先生成新的明文 ZIP：

```text
encrypted/
  ENCRYPTED_BACKUP_INCOMPLETE       # 开始阶段证据
  backup.pgp                      # 标准 RFC 9580 二进制 payload
  ENCRYPTED_BACKUP_COMPLETE.json   # 最后原子发布的完成凭据

backup.pgp 内部：workspace-b3-v1.zip
  manifest.json
  database.dump
  BACKUP_COMPLETE
  BACKUP_INCOMPLETE（如原集合包含）
  knowledge/sources/<uuid>/<revision>.source
```

内部完整保留 B3 Manifest、custom archive、所有七个 Knowledge 文件和原完成标记；
旧 Manifest 的 `UNENCRYPTED_SYNTHETIC_ONLY` 保持其原含义，外层另定义 encrypted format/version 1，没有静默改标旧集合。
原文、表计数、逻辑数据库名、文档/文件元数据、时间和私有摘要均在加密 payload 内。
OpenPGP 公共头只含解密必要算法/成本/salt 等信息；外层完成 JSON 只含固定 format/version/profile、状态、payload 名、大小与密文 SHA-256。

输出目录必须全新；先写 `backup.pgp.pending`、完整关闭加密流并 force，再同目录 ATOMIC_MOVE 为 payload，
最后原子发布 `ENCRYPTED_BACKUP_COMPLETE.json`。失败或中断没有最终凭据，不能视为完整集合，不覆盖旧备份。
开始阶段标记保留，最终凭据才是完成依据。SHA-256 用于定位密文一致性，不能代替 OpenPGP 认证。
外层 version 与 packet profile、内部 literal 名/version、B3 format 版本均检查，没有降级回退。
