## 实际功能

生成候选后可主动点击“检查已有记忆”。系统复用已有字面搜索和单条读取，对使用中的记忆核对正文是否与候选**完全相同**；标题或类型不同仍能发现同正文记录，仅标题命中或正文只是包含候选则不判为重复。读取仅供当前候选审核，不会把已有记忆发送给模型。

查到重复时显示对应标题／版本，采用前需勾选“我已了解重复项或检查限制，仍要采用候选”；也可直接丢弃候选。读取失败、版本变化或检查不完整同样要求显式确认才能继续采用。仍须在原编辑器点击“保存”才写入；不会自动覆盖、合并、归档、删除或创建记忆。

检查是可选的，用户未点击时不会新增读请求；它不是全局唯一性约束。编辑候选会清除旧检查和确认，需重新检查；本轮观察也不保证之后没有新记录或其他客户端修改。

## 范围与实现

- 取候选正文前 160 个 Unicode code point 作为字面查询（精确重复必含此前缀），查询 ACTIVE、全部类型、第一页。最多一条 `memory.list` 和 20 条串行 `memory.get`，不扫描全部历史或全库正文，不新增接口／schema／模型依赖。
- 每条读取需与搜索结果的 ID、revision 及 ACTIVE 状态匹配，才比较完整原文。比较区分大小写，不去空白、不规范化换行或 Unicode，也不判断语义相似。归档记录不在范围内。
- 匹配总数超过 20 时明确显示不完整；读取失败停止后续读取，记录变化亦标为不完整，不把检查失败显示为“没有重复”。界面分别显示搜索匹配数、实际已核对数，以及“已核对记录中未发现”的有限结论。
- 编辑／重新生成／丢弃候选、session 重置、组件卸载会隔离迟到结果；禁用期间中断仍在进行的检查。已完成的重复提醒不会仅因临时禁用而消失。进行中的检查阻止采用，重复点击不产生重叠扫描。已发送的单次读取不能撤回，但结束后不会继续旧扫描。
- 复用现有存储合同，候选与查重结果只在当前组件内存中；正文不写 URL、浏览器持久存储或日志。生产变更仅两个前端文件，不改变 Native／Java、模型配置、服务或安全设置。
