# 明确选择多份资料进行检索

日期：2026-11-11。源码基线 `b10316b017d7e91e11a11f9bc79bc01dc53ca377`。

## 已确认缺口

资料导入、原文阅读、检索命中定位、知识问答、记忆草稿和对话参考已有入口，不重复增加这些入口。仍存在一个影响多份项目资料使用的限制：`KnowledgeScopePicker` 和单次检索合同只允许一份文档的明确版本或全部可用资料。导入一组文件后，用户无法同时限定只查这组资料。

## 本次实现

“查找资料”现在可以从文档列表逐份加入检索范围，最多 10 份。选择固定到 documentId/sourceRevision，显示文件名与版本；同一文档不会重复加入。资料更新后只可通过明确的“更新当前资料的所选版本”改变选择，列表刷新不自动更新范围。保留“限定为当前文档”和“使用全部资料”操作。移除最后一份后保持空范围并禁用查询，不能悄悄变成全库。

一次点击检索，沿用既有受限 Bridge/Runtime API，按所选顺序逐份读取，每份最多 10 个命中；不新建后端 API、schema、依赖或模型流程。各请求都携带唯一文档及明确版本，不把标题作为筛选条件，不请求全库再做本地过滤。返回来源必须匹配请求范围，否则拒绝该组结果。

结果按文档分组，分别呈现命中、无匹配、失败和尚未查询。某份更新／归档／删除导致失败时，其他成功结果仍可查看，但整体明确标为不完整；不能把失败当作零命中。索引拒绝时停止后续查询。每组仍可打开原始精确位置，沿已有阅读流程用于记忆或对话；知识问答的范围保持其独立、既有单文档／全库合同，没有宣称支持跨多文档限定问答。

每份查询独立完成，因此没有跨文档一致性快照或全局 top-N 排名保证。资料集合变化、离页和会话轮换会使在途结果失效并停止后续读取；不自动重放查询。离页／会话轮换按既有规则清除查询与范围。没有将内容、ID 或查询持久化到浏览器存储。
