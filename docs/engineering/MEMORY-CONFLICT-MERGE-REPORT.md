# 记忆版本冲突的三方合并

2026-11-11，基线 `c5def891f3b318551e09eaa1611d20f5f07ae820`，分支 `codex/knowledge-version-compare`。

## 缺口与交付

对照当前 V1、ADR-004、已交付的记忆修订恢复和实际 MemoryPage 后，确认原流程只展示最新已存正文，要求用户自行将最新修改合并到本地草稿。对于从资料或对话整理的项目笔记，另一个窗口改了不同段落时，用户仍须人工判断全部差异，容易遗漏远端修改。

本次补齐一个独立业务流程：版本冲突 → 读取最新记录 → 以最初加载的记录为共同原文准备三方合并 → 逐项处理冲突并预览完整结果 → 再读最新记录核对 → 采用到编辑器 → 用户单独点击保存。原手工对照流程保留，不涉及新的数据库接口、历史正文持久化或模型调用。

准备时分别比较类型、标题、正文。未改的一边采用另一边，同样的修改只保留一次；正文通过逐行差异把不重叠的改动组合。重叠修改、删除与修改、同处不同插入需要用户明确选择一边或填写合并文本。插入紧邻替换边界时保守地交给用户审阅。未解决的冲突不产生可采用结果，不插入冲突标记、不猜测语义、不截断超限正文。

完整预览包含最终标题、类型和全部正文。取消预览不改变草稿。采用前重新读取同一 ID，核对完整最新记录与准备时相同，同时核对本地草稿、页面代次与连接会话；任何变化保留草稿并要求重新准备。采用只更新编辑器内容及所依据的 revision，后续明确保存仍走原 expectedRevision 并发检查。缺失、归档、身份变化或未知写入不能经此入口绕过限制，未知写入不会自动重发。

## 参考实现、许可与维护

- 参考 [VS Code 的三方合并交互](https://code.visualstudio.com/docs/sourcecontrol/merge-conflicts)：展示共同原文、两侧修改与最终结果，逐项决定后再完成。其[开源源码许可证为 MIT](https://github.com/microsoft/vscode/blob/main/LICENSE.txt)。这里只采用交互思路，没有复制编辑器代码或引入 VS Code 依赖。
- 差异计算复用仓库已锁定的 `diff@9.0.0` / [jsdiff](https://github.com/kpdecker/jsdiff)，BSD-3-Clause。当前上游[维护记录](https://github.com/kpdecker/jsdiff/blob/master/release-notes.md)包含 10.0.0 prerelease 工作；不能将其当成本项目使用版本，也不把空 GitHub Releases 页面称为发布验收。没有升级或下载包，原 `ThirdPartyNotices/jsdiff.txt` 与分发许可流程不变。
- 本次只调用 `diffLines`，不用外来补丁解析或 applyPatch。每侧正文最多 2000 UTF-16 单位，每次差异有 100 ms 协作式期限及 4000 次行编辑上限；不是独立线程的硬超时。失败保留原手工恢复路径。
