## 用户控制与保留行为

会话消息下新增折叠区“保存或恢复草稿文件”，清楚说明窗口内草稿不会自动落盘。保存生成当前消息的明文副本；用户自己选择位置，已有文件不会被覆盖。文件持续保留，后续编辑、发送、退出不会更新或删除它，用户可自行保管／删除。它保存最后一次明确保存的快照，不是自动保存、崩溃日志或完整工作区备份；保存之后尚未再次保存的修改不保证恢复。

只保存消息文字、会话 ID／创建时间、当时标题／轮次数及保存时间。未保存的会话标题、尚未插入的参考列表、历史内容、原生记忆选择／连续使用权限均不进入文件。正文允许 1–3000 UTF-16 单位的有效 Unicode；文件上限 32 KiB。保存允许文字超过发送的 UTF-8 预算，以免因中文输入预算丢失草稿；恢复后既有发送长度检查仍会要求用户缩短，不截断。

重开后需用户先选择原会话，再打开文件。Native 首先要求当前 session 已知该会话，文件中的 ID 不授予新权限，也不据文件内容读取别的 ID。打开文件后仅查询已授权当前会话，核对 ID、创建时间及 ACTIVE 状态；缺失、归档或身份不符则停止。标题变化不会伪装成另一个会话，恢复预览同时显示当前标题与文件所记标题。

恢复确认默认取消；对照当前消息与文件消息，并提示文件可能已经发送过、需要核对历史。明确确认后才清除当前记忆选择并替换消息；清除失败不替换。会话／页面代次、当前 ID／创建时间、原草稿再次核对，后来编辑不会被覆盖。文件内出处仍是可编辑定位线索，既不自动读取来源，也不重新获得已验证引用；消息中的指令不会因此获得额外权限。确认恢复后还需用户自行发送。

## 实现与写入边界

新增 `ConversationDraftFile` 版本化文件格式及有界严格读取：固定 Markdown 外壳内仅接受六个 JSON 字段，拒绝缺失／额外／重复字段、不支持版本、无效 Unicode 和过大文件。内容按纯文本展示，不执行 Markdown、HTML 或链接；文件元数据可编辑，不当作签名来源证明。记录的 `ToString()` 隐去正文。

保存复用 `NativeKnowledgeAnswerExport.SaveNewAsync` 的本地路径、非链接检查、当前用户文件保护、同目录临时文件及不替换发布；打开复用 `NativeKnowledgeSourceFiles.OpenRegular` 的持有句柄、实际文件类型／最终本地路径和上限检查。新入口仅接受 `.workspace-draft.md`，不改变既有安全检查或默认配置。没有自动目录扫描、Profile 草稿存储、localStorage 或隐式写入。

Bridge 新增 `conversations.saveDraft`／`conversations.openDraft`，仍执行既有文档来源、session、唯一请求 ID、白名单、字段和传输预算验证；文件对话框超时沿用 300 秒。Native 每次保持 session 生命周期、单个草稿文件操作和已知会话检查；旧 session 回执不发布。保存回执不明时保留草稿并要求检查所选位置，不自动重试或清理可能已经发布的文件。Runtime 只 GET 会话信息，没有新 API、数据库 schema、模型调用或领域写入。
