## PostgreSQL 实现

- 新资源：`src/main/resources/db/workspace/migration/V1__memory_conversations.sql`。
  独立 `workspace` schema、Flyway history，与 Finance `public` / V1–V21 完全分开。
- 表：storage_metadata、write_lock、memory_items、conversations、conversation_turns、
  conversation_messages、conversation_memory_selections、sqlite_import。
- 保留字符串 ID、字段及 bigint epoch 毫秒，不使用隐式时区转换。ID 采用 C 排序；
  保留唯一性、级联、不可变消息/选择和终态触发器。历史选择没有新增当前 Memory FK。
- `MemoryStore`、`ConversationStore` 复用业务 API，新增 DataSource 构造路径；不复制一套业务服务。
  PostgreSQL 写事务锁定单一 write_lock 行，保留原跨 Store 写入仲裁；读事务为只读 REPEATABLE READ。
- Memory 搜索对有界源表使用参数化 strpos，保留大小写敏感、字面子串和标点/Unicode 语义；
  不依赖需要额外扩展或索引角色权限的 pg_trgm。
- `WorkspacePostgresqlConfiguration` 只接收显式 loopback URL 和外部凭据，独立 DataSource，
  不作为 Finance 默认候选，不在启动执行 migration；拒绝用 superuser/DDL 角色作普通 Workspace 连接。
- `workspace.persistence.backend` 默认仍为 sqlite。显式选择 postgresql 后出错直接拒绝，不回退 SQLite。
- Workspace 逻辑备份导出使用同一 PostgreSQL 读快照。PostgreSQL 模式的旧 SQLite restore 入口拒绝执行；
  新的 PostgreSQL 逻辑恢复路径尚未交付，不能默默发布新的 SQLite 权威。
- 没有修改 Provider、模型调用、Native Gate、MMF-3 ACL 或 Browser 安全边界；无新增依赖/应用进程。

## 受控迁移路径与安全行为

`SqliteWorkspaceMigration.migrate(source, backup, workspaceDataSource)` 为显式离线 Java 维护入口，无 HTTP 或启动钩子。

1. 操作者必须停止 Runtime 并保持停写至后续明确批准的切换。工具额外持有源 SQLite BEGIN IMMEDIATE，
   阻止调用期间的其他写入；工具返回后不代表已经执行停写/切换。
2. 验证源为已有普通文件，无链接，现有私有权限符合合同；只读验证权限，不修复原文件。
3. 在已验证私有目录 CREATE_NEW 新备份文件，使用真实 SQLite online backup API，从另一只读连接取得一致性备份，
   不盲复制活动数据库。失败保留备份，不覆盖旧备份。
4. 检查 user_version=3、完整性、外键、表/字段白名单、UUID、业务文本、序号/消息关系；未结束 PENDING 拒绝迁移。
   旧版本须先另行受控升级；不自动猜测 schema。
5. 验证源与备份的行数及所有源字段摘要。只迁移五张真值表，不复制可重建 FTS 内部对象。
6. `importSnapshot` 也可接收已经隔离的 SQLite Connection，固定源读事务；这是数据库导入原语，
   不替代真实文件的私有权限和停写流程。
7. 目标须已显式 migrate 且所有业务表及 receipt 为空。单个 PostgreSQL 事务内导入、比对行数和逐字段规范摘要，
   再写一次性 receipt；任何中间失败回滚本次全部导入及 receipt。
8. 提交后另开连接验证数据和 receipt 可见。提交状态不确定时只报告固定阶段/SQLSTATE，
   保留现场并要求检查 receipt；不自动重试、清表、覆盖或切回 SQLite。
9. 成功后保留原 SQLite 和一致性备份；正式停写、切换和用户数据迁移仍需后续明确授权。
