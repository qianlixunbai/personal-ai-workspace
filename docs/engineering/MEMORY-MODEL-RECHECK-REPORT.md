## 结论

候选的连续摘录和语言限制得到改善，但生成质量仍不稳定：最后一次完整尝试在“否定／修订”场景缺少 `evidence`，生产解析器以 FORMAT 拒绝。没有修补、采用或保存该输出。不能用之前某轮的成功覆盖这个失败，也不能将零候选率、结构合格率或总体准确率由这些小样本推断出来。

会话暴露了另一实际问题：清除显式引用后，模型声称历史中的颜色事实已经不可用，尽管前两轮助手消息仍在请求里。修正生产 `ConversationContext.SYSTEM` 后，最后一次**仅会话**的 3 轮复验通过，模型明确承认旧历史仍可包含事实。它没有重跑候选，不能称为整组通过。

## 成熟实践与本次修正

沿用 [Mem0 / LangExtract 的许可、维护、适配和资源评估](MEMORY-CANDIDATE-GROUNDING-REPORT.md#成熟实现评估与复用)，继续直接复用生产提示／解析器、现有原生会话组装和测试框架；没有新增第三方运行时、自动重试器或模型写入能力。

- 纯 Latin 来源中的中文翻译可能夹带原有英文名称，原先“候选必须全部属于另一文字体系才拒绝”的规则漏检。本次对至少 8 个字母且全部 Latin 的来源，拒绝标题／正文引入任意 Han 字符；保留原来纯 Han 来源的明显整段 Latin 偏离拦截。混合来源、短文本和同一文字体系内的翻译仍不能自动判断，不能把它称为语言识别器。
- 纯 Latin 来源使用英文示例；其余来源使用带项目范围的中文偏好示例。明确 PROJECT_NOTE 表示项目决定、PREFERENCE 表示长期个人偏好，移除通用 JSON 模板中暗示默认 PREFERENCE 的值。要求摘录包含完整句子及解释适用范围所需上下文。只改变生成约束，不把失败输出改写成成功输出。
- 保留实际来源、原始结果、严格字段与字面 evidence 校验、显式审核和保存。新增真实失败记录回放：中英混合翻译拒绝为 LANGUAGE，缺少 evidence 拒绝为 FORMAT，首次改写证据的历史输出继续拒绝为 EVIDENCE。
- 真实模型脚本补充项目范围、类型、归属和历史清除场景的断言，记录合同与 fixture 检查结果；支持显式 `scope=conversation`，默认仍为全组。`semanticReview: NOT_PERFORMED` 保留在原始机器输出，另存语义审阅结果，绝不改写机器输出。
- 会话系统提示说明：清除只停止后续显式引用，不能删除已提供的历史，也不能声称这些历史不可用。仍把记忆作为不可信数据，不授予工具或外部操作能力。提示从 363 增至 494 UTF-8 字节，仍在 512 字节限制内；没有扩大上下文、输出或字符预算。代价是接近边界的输入容量减少，原来 1,810 个汉字的预算测试现在应拒绝；1,760 个汉字的实际提供器 JSON 加输出预算仍可容纳。测试同时覆盖这两个边界及长模型名的拒绝，未放宽预算。
