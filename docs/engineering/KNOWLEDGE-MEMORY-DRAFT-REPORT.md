# Knowledge 回答转记忆草稿

2026-11-09；基线 `ceeaafa75aa6a6b0763897707c9fff105b4119d4`，分支 `codex/knowledge-version-compare`。Development-only，仅本地源码增量。

## 选择与实现

当前显式 Memory 已有候选审阅、查重、修订、显式保存和会话使用闭环；会话接纳回执也已存在。本轮不重复实现这些能力。Knowledge 已有持久回答和导出，但成功回答无法直接进入同一 Memory 审阅流程，因此补齐这一人工选择入口。

- 成功的当前回答及重新打开的历史回答新增“整理为记忆草稿”。使用经过现有 Bridge 契约验证的回答原文，不混入未发送问题、渲染后 Markdown 或当前编辑框修改。
- 通过既有 App → MemoryPage 草稿接收器，固定来源角色为 ASSISTANT。仍提示助手内容未经核实；只有用户点击“生成记忆候选”才调用模型，只有明确“保存”才写入 Memory。
- 不把回答变成已确认个人偏好。Memory 类型仍默认 PROJECT_NOTE，标题为空，用户需整理及审阅。正文超限完整保留且禁止保存，不截断。
- 复用已有未保存草稿替换确认、重复保存锁、保存结果未知时禁止重发、会话重置清除机制。禁用、隐藏、忙碌或非成功回答不能触发入口。
- 提示用户先核对引用：此次仅传递回答文字，引用链接不随草稿保存，源文档更新不会自动修订 Memory。它不是持久来源关联、自动记忆、事实核验或历史版本追溯。
- 原有“从对话”提示改为“从来源”，保留 USER／ASSISTANT 归属；原对话路径行为不变。

复用现有 React、WorkspaceClient、MemoryCandidatePanel 和原生保存边界；没有新增依赖、许可证负担、schema、后台服务或模型调用链。为这一明确的人工作业流引入外部记忆框架只会重复已受控的保存／审阅逻辑，因此不增加依赖。
