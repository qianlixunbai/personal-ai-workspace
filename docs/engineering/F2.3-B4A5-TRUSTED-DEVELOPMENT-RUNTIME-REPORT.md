## 3. Bearer 与可信诊断

Bearer 由既有 Java LocalClientToken 生命周期在固定私有文件生成。owner 复用 CredentialStore 的有界、owner/ACL/共享句柄读取校验，并要求受保护 DACL，只在本次进程内存中使用。
没有自动导入 Credential Manager，也未把 token、数据库密码、路径或原始 stderr 传给 React。

stdout/stderr 均持续、有界地读取；每个 pipe 累计超出 1 Mi 字符即停止本次子进程。stderr 单行最多 160 字符，只识别精确 `WORKSPACE_STARTUP_V1` 固定枚举；多条有效诊断退回原因未知。未知文本不显示、不保存为任意日志诊断。
READY 必须由本次存活子进程、真实 Health 与 Native Bearer 认证共同建立，不能由 stderr 宣告。
状态覆盖 STARTING、READY、准入/配置/凭据/数据库/结构拒绝、超时、提前退出、取消及原因未知。

## 4. WPF / Bridge / React

复用 AssistantApp、RuntimeClient、StorageStartupStatus 和原会话 Bridge；SQL 状态查询前重新确认 owner 就绪，返回后再次确认子进程未失效。
新增有界的 `storage.lifecycle` 类型化通知，捕获 session 并在 UI dispatcher 实际投递时复核；旧会话和关闭后通知丢弃。没有扩大请求预算或加入持续轮询。
React 收到失效状态就清空旧数据库结果并使进行中的旧响应失效；页首通过现有 shell.refreshStatus 重查，使用请求版本防止旧启动观察覆盖新结果。
启动属于 Desktop lifetime；WebView 会话轮换只作废该会话的观察/响应，不重启或转移 Java 所有权。
Desktop ExitAsync/Cleanup 停止本次 Java；仅关闭 Main Workspace 窗口仍保留托盘，沿既有桌面生命周期。
