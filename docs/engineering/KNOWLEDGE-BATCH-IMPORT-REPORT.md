# 资料批量选择与逐份导入

日期：2026-11-11。源码基线 `fbf58a7e35ad6723e7aabd182409e5ba2f2c4cde`。

## 缺口与实现

现有资料入口的原生选择器固定 `Multiselect=false`，一次只能导入一份文件。为整理多份项目资料，新增“批量导入文件”：原生选择多份 → 核对清单 → 明确开始 → 逐份上传及等待解析 → 查看各项资料／处理失败。它复用已有资料存储、解析和版本规则，不新增资料格式、数据库、后台监控或模型行为。

一次最多选择 10 份，待导入正文合计最多 32 MiB；单份仍遵守原有 8 MiB 上限。TXT/Markdown 使用原有本地普通文件句柄检查；Word/PDF 复用既有提取器和原生摘录确认。取消任意摘录确认会取消整次选择，此时尚未上传。无需新增依赖或另一套导入组件。

界面只收到显示文件名、正文大小和宿主生成的请求 ID，不收到路径或源字节。已选择流归当前 Bridge 会话所有，未提交流在明确结束本批或会话结束时释放。提交前先移除对应选择，重复请求不能再次上传同一流；上传沿用既有 Runtime API，响应丢失时仅查询原请求。新批量选择的作用是创建新文档；更新既有版本仍使用原“导入新源版本”入口。

用户确认后顺序处理，每份达到 READY 才自动开始下一份，避免填满后台解析队列。等待期间每秒只查原请求，最多查询 120 次后暂停。可以暂停后续上传；离开资料页或页面不可用时也暂停，保留已返回的回执。已发出的当前请求不因暂停而宣称撤销。

遇到失败、未知提交或状态读取失败，保留逐项结果并暂停后续文件。未知项只能检查原请求；查不到不等于没提交，不会重新上传。检查成功后仍需用户明确继续。可放弃尚未提交的文件；待确认项仍留在清单。清单是窗口内状态，不承诺退出后的队列恢复；已受理的资料继续遵守现有 Runtime 持久化合同。
