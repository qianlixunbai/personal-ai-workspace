## 用户流程与边界

1. 在 Conversations 当前已加载的持久历史中，点击某条用户消息或助手回复后的“保存为记忆草稿”。PENDING 轮次不提供该操作；失败轮次只能选择实际用户消息，不能选择错误说明。
2. App 将一条消息的完整原文以内存态交给现有 MemoryPage。默认 `PROJECT_NOTE`、空标题；不生成摘要、不改写、不截断。
3. 如果隐藏的 Memory 编辑器已有 dirty 修改，沿用现有丢弃确认。取消保持原草稿和 Conversations 路由；明确丢弃后才接收并进入 Memory 新建模式。编辑器有进行中的操作时拒绝接收，提示稍后重试。
4. 编辑器提示“已从对话填入草稿；尚未保存，请检查内容”，并提醒助手回复可能不准确。用户填写标题，可改类型、正文，再点击既有保存按钮。
5. 只有保存才调用既有 `WorkspaceClient.createMemory` → `memory.create` → Native Bridge → Runtime Memory 创建 API。保存后的反馈、revision、dirty、冲突及 OutcomeUnknown 处理继续沿用原实现；不自动重试。

草稿不使用数据库、浏览器持久存储或 URL 正文参数；不保存来源外键，不向模型发送，不自动选为后续上下文。来源仍采用原创建合同的 `MANUAL`。正文完整保留于 React state；即使 textarea 的 DOM 显示规范化 CRLF，未经用户编辑的原始 CRLF 仍由保存 payload 保留。

超限或不合法正文完整展示并给出明确错误，继续使用 `validContent` / `validDraft` 禁止保存。Native / Java 校验合同保持不变。
