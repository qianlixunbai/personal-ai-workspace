# 从查到的资料到当前会话草稿

2026-11-10，接续 `4d40388`，产品提交 `3f8167f`，分支 `codex/knowledge-version-compare`。完成一个完整核心模块：**明确挑选资料原文／记忆正文 → 预览带出处的完整消息 → 回查或移除 → 核对来源后插入当前会话草稿。** 本轮没有把同一流程拆成多个模块计数。

## 选题依据与完成判据

先核对原 V1 目标、当前路线图、上一轮三份交付报告以及 App／ConversationsPage／WorkspaceSearchDialog 的实际实现。统一查找已有只读原文，Conversation 也已有原生显式记忆选择，但两者之间没有准备可审阅参考消息的入口。相比继续增加查找筛选，这条链可以直接帮助用户把已有资料用于正在写的问题。

输入是当前活动会话的未发送草稿、用户主动选择的最多四段文字：完整 Memory 正文，或已验证 Knowledge 预览页内的连续原文选区。输出是保留原草稿前缀的完整、可编辑消息，附名称、准确 ID、版本和资料绝对偏移。完成判据为：选取／回查／移除可用，预览与实际插入一致，缺失来源不回退，超限不截断，关闭或失败保留草稿，迟到回执不写入另一会话、另一会话代次或后来编辑的草稿；准备过程中不发送或保存。两项新增合成流程已验证这些主要边界。

## 用户流程与范围

在会话编辑区点击“准备会话参考…”，打开复用工作区查找的临时面板。资料仍须先阅读再选择当前预览内的文字；记忆仍须读取并核对列表 revision／状态后才能加入。重复来源范围不会重复加入。准备列表展示原文、来源位置和目标会话，支持移除及主动回查；每次回查重新读取准确来源。资料选区按绝对偏移标注，不把原检索命中的行范围冒充用户选区。

完整消息预览包含原草稿、所选原文和出处文字，长度按既有 3000 UTF-16／5632 UTF-8 字节限制检查。过长时保留全文并阻止插入；用户可移除参考或关闭面板后缩短原草稿。原生“选择记忆”及按预算纳入的历史没有混入此预览；实际发送仍由既有 Runtime 检查全部输入预算。

“核对来源并插入草稿”只做既有只读请求与本地草稿赋值。Memory 必须仍是相同 ID／revision／状态／标题／正文；Knowledge 必须仍有相同文档及指定源版本，并完整读回同一范围、逐字匹配。新版本发布不替代所选旧版；指定版本缺失、读取失败、源内容不同则整组停止，不插入部分结果。逐项核对不是跨领域事务快照；核对后来源仍可能变化，已插入文字是用户审阅过的副本，不自动同步。

插入目标绑定会话 ID、页面代次、活动状态和原草稿内容。切换会话、离页、不可用、重置 session 或关闭面板会撤销准备；原会话或草稿变化则拒绝覆盖。关闭会丢弃未插入的参考选项，保持原编辑内容。明确插入后仍须用户自行编辑／点击“发送”，测试没有代替用户执行发送。

资料和记忆中的指令只是原文文本；出处只是可编辑定位线索，不成为受信事实、Runtime 绑定引用或原生记忆授权。历史对话搜索结果仍仅供阅读。没有新增 API、schema、索引、Native 权限、模型请求、自动 Memory 保存或持久参考列表。输入预算之外的系统／历史上下文也没有被冒称为完整模型预览。
