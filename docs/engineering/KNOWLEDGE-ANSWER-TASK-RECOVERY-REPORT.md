# 单份知识问答的原任务恢复

日期：2026-11-11。基线 `e09dad4509da3536f1cce61d77356b9726384bb7`。

## 缺口与结果

单份问答的 Bridge 已校验任务 ID 与响应合同，但组件在额外核对引用范围失败时先抛错、后保存任务，导致已知编号被丢弃，并被显示成无编号的未知提交。取消请求失败后也没有按任务记住取消意图，允许再次发送取消。这与已实现的逐份问答恢复语义不一致。

现在先保存受理编号和原输入，再采用范围一致的回答。范围异常不展示回答／引用、不伪造 QUEUED 状态、不允许新问题覆盖未核对任务；用户可按原编号读取或请求一次取消。取消失败／结果未知后继续保留取消标记，后续 RUNNING 及切页不能重新启用取消。只有合法任务终态才解除等待。原编号和取消集合只属于当前 Bridge 会话，session 变化清空，迟到回执继续按原代次丢弃。

沿用既有任务 API、Bridge 身份校验、固定版本和历史持久化；没有新后端、自动重发、模型调用或安全准入变化。原有无编号的未知提交仍阻止重发，历史相似记录不能解除它。
