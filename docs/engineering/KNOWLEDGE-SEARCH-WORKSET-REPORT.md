# 检索工作集的手动保存与恢复

日期：2026-11-11。源码基线 `6390a0d71b69856d498a865eedb5d65f3783ffa7`。

## 用户流程

切页保留不能覆盖应用关闭后的资料重选。此次在“查找资料”增加“保存或恢复检索工作集”：明确选择 1–10 份资料后，可将关键词（允许空草稿）、文档 ID、固定源版本、文档标题／创建时间以及保存时间，手动保存到新的 `.workspace-search.md` 文件。保存前由 Native 读取已授权资料的元数据，确认指定版本存在；不信任前端提供的标题或创建时间。

重新打开应用后，用户选择文件，程序先沿现有使用中／归档资料列表核对当前资料身份，再读取匹配文档的版本信息。预览显示当前与待恢复的关键词、每项固定版本以及核对结果；确认后只替换检索清单与旧检索结果，不执行查询。用户再明确点击检索，或者准备所选资料的逐份问答。标题变化会显示新旧名称；资料缺失、身份不符、归档、所选版本丢失、当前版本变化或读取失败都会保留该项和原因，并阻止该清单检索或准备问答。用户须明确更新版本／移除该项；移除全部也不会自动改成全库。

文件是明文、可编辑的输入快照，不是资料或任务备份，不保存命中片段、资料正文、问答、导入回执或未知提交。不会自动保存、重新查询、发起问答、取消、上传或重放任务。原有导入与问答任务不被恢复清单覆盖。打开过程中或确认前有新编辑时保留新草稿；切页、连接会话变化、资料集合刷新使旧核对失效。保存结果未知时提示先检查目标位置，没有自动重试。

## 合同与保护

- 两个新增 Bridge 方法：`knowledge.saveSearchWorkset`、`knowledge.openSearchWorkset`，只接收受限关键词／明确 ID 和版本或空对象，不接收文件路径。Native 文件对话框由用户选择位置。
- 复用既有会话草稿／问答导出的 `NativeKnowledgeAnswerExport.SaveNewAsync`：受保护的同目录暂存文件、新文件创建、禁止覆盖既有文件、禁止链接及网络路径。复用 `NativeKnowledgeSourceFiles.OpenRegular` 的实际句柄验证、有界读取，只增加工作集后缀入口。没有放宽原保护、Profile／所有权准入或任意路径 Bridge。
- 文件版本标头与固定字段、严格 UTF-8、32 KiB 上限、最多 10 个不同文档、版本 1–10、关键词最多 128 个 Unicode 字符。错误格式或额外字段不进入恢复。新增 C# 合同仅静态核对，尚未编译或原生运行。
- 从文件读取的 ID 不授予文档或任务权限；恢复先获取当前配置的受控列表（每种状态最多 25 页），身份匹配后才读取详情，不读取正文。预览不是事务快照或来源真实性证明；实际查询仍由已有 Runtime 范围／版本合同裁决。无数据库 schema、Runtime 服务或依赖变更。
- 保存文件操作有互斥与会话代次校验；前端保存超时／通信结果未知保持未知语义。文件操作没有修改真实用户数据的实验路径。

## 最少验证与未验收边界

`tsc --noEmit` 在最终产品代码及新增测试写入后通过。只新增并运行三个直接流程场景：

1. 明确版本保存，卸载页面并创建新客户端后打开核对，标题变更可见，确认恢复不发查询；点击检索才按原固定版本逐份查询。
2. 缺失／版本变化／归档／身份不符保留为阻断项；未授权的文件 ID 不直接获取详情；显式移除与更新后才查询，空范围不扩展。
3. 未知保存不自动重试，格式异常／迟到打开不覆盖新草稿，资料刷新使预览失效，确认前编辑受保护。
