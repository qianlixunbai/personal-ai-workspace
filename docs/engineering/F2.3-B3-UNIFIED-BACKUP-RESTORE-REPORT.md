## 3. 离线入口、停写与一致性

`UnifiedPostgresqlBackup.backup/validate/restore` 是受控离线 API，另提供同类 `main`：

```text
java -cp <compiled-runtime-classpath> io.github.qianlixunbai.workspace.backup.UnifiedPostgresqlBackup backup <private-config.json> --writers-stopped
java -cp <compiled-runtime-classpath> io.github.qianlixunbai.workspace.backup.UnifiedPostgresqlBackup validate <backup-directory>
java -cp <compiled-runtime-classpath> io.github.qianlixunbai.workspace.backup.UnifiedPostgresqlBackup restore <private-config.json>
```

CLI 只读 owner-private 配置文件；口令不进命令参数。字段由准备脚本生成，不能把配置文件提交或复制到公开目录。
默认准备可用于原 test 库的基础 CLI 备份。非空集成准备显式使用
`prepare-unified-backup-test.ps1 -BootstrapBackup <trusted-original-test-archive-directory>`，新增第三个合成源库。
`run-unified-backup-test.ps1` 只运行下面的聚焦 Maven 流程，并默认执行任务凭据收尾；未实际执行该包装脚本本身，
本轮直接执行了等价 Maven 命令和准备/收尾脚本。

备份必须明确声明 Runtime 与其他写入者已停止；未声明即拒绝。
数据库拒绝其他现存 client session，取得 Knowledge admission 排他 advisory lock，并对实际全部业务表持有 SHARE 锁，
阻止 DML/结构变更。短期备份角色的 UPDATE 权限仅为 PostgreSQL SHARE lock 准入；代码不向源表发 DML，也不给它 schema CREATE。
PENDING/PARSING Knowledge jobs、未完成 deletes 或 PENDING Conversation turns 均拒绝备份，保留现场而不重放模型/清除删除意图。
所有 revision 文件持有 Windows NOSHARE_WRITE/NOSHARE_DELETE 只读句柄至完成；复制前后重复核对文件和数据库摘要，
并用另一连接复查当前源状态。操作者须持续停写，不能以 pg_dump 快照代替文件停写。
这不是抵御管理员/同 SID 任意篡改或不受控 DDL 写者的通用在线备份方案。

Manifest 与 `pg_dump --snapshot=<pg_export_snapshot()>` 使用同一个 REPEATABLE READ 导出快照。
`database.dump` 为官方 **custom archive (`--format=custom` / PGDMP)**；最终非空 archive 为 **173145 bytes**。
服务器、pg_dump、pg_restore 均实际为 **17.11**；本轮合同保守限定 major 17，不承诺已验证其他 major。
官方工具语义见 [pg_dump 17](https://www.postgresql.org/docs/17/app-pgdump.html) 与
[pg_restore 17](https://www.postgresql.org/docs/17/app-pgrestore.html)。

## 4. Knowledge 文件合同与 Manifest

只复制真值引用的 `sources/<canonical-uuid>/<revision-1..10>.source`，不打包未知 staging、缓存或 lexical.db。
当前表示正文与 locators 存在 PostgreSQL revision 的 text/locators 字段内，没有第二份必需的外部表示文件；
两者随 archive 保存。校验逐 revision 比较源字节、type、parser/normalizer、规范化正文、locator JSON、
representation digest、行数及 artifact bytes，保留原 imported 时间和 revision 语义。

Manifest format 1 包含格式/状态、UTC 时间、数据库逻辑名称、major/server/tool versions、两个 schema、两套 migration versions、
全部表数量及逐字段完整行摘要、结构摘要、序列状态、archive 大小/SHA-256、revision 相对路径/长度/源 digest/表示 digest、
索引引擎 `postgresql-token-bm25-1` 与必须重建要求、明确排除项。没有密码、Windows Token 或原设备绝对恢复路径。

校验拒绝未知格式、错误 major、未知字段/重复 JSON key/尾随内容、缺失完成标记、摘要或文件签名不匹配、重复相对路径、
路径穿越、非规范 UUID/revision 路径、链接/reparse point、目录与普通文件混淆及未声明 payload。
备份只创建新目录；逐文件 flush 后写 Manifest，数据库 snapshot/连接清理成功后，完成标记先写入 `.pending` 并 force，
再以文件系统 ATOMIC_MOVE 发布 `BACKUP_COMPLETE`；恢复的 `RESTORE_VERIFIED.json` 使用同一发布方法。均不覆盖旧集合。
`BACKUP_INCOMPLETE` / `RESTORE_INCOMPLETE` 保留为开始阶段证据；只有有效的最后完成文件才代表完成，
没有最终文件的集合始终未完成。恢复候选不接入 Runtime。

SHA-256 只用于一致性/意外损坏检测，不是认证或恶意篡改防护。
修改 Manifest 的负向检查即使重新计算完成标记，重复路径/穿越仍会被结构规则拒绝。
未经认证的外来 SQL archive 不可信，不能因为 SHA-256 正确就执行。
