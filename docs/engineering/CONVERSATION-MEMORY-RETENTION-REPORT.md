# 当前会话明确授权的连续记忆使用

2026-11-07。基线 `22f0ddf5b5f02388654b6ba0dc85bae40954d8aa`，分支 `codex/recovery-v3-workspace-core`。本阶段交付选择授权的跨轮使用逻辑，仍为 Development-only。

## 缺口判断

| 链路 | 已有能力 | 本轮判断 |
| --- | --- | --- |
| 提取与审核 | 对话转草稿、主动模型候选、原文摘录对照、编辑、有限重复检查、明确采用后保存 | 真实模型质量仍未验证；增加候选查看控件无法解决已保存记忆的使用摩擦 |
| 持久化 | 现有 Memory Store、版本控制、编辑／归档／删除及乐观并发校验 | 已能保存用户确认的内容；本轮不改变数据格式 |
| 检索与选择 | 主动字面搜索、原生预览并选取最多 4 条、按版本引用 | 缺少语义召回，但无安全模型验证边界时不引入新的模型／向量服务 |
| 对话使用 | 每轮校验、快照、上下文预算与接纳范围回执 | 每次发送后消耗选择，连续讨论时需反复选相同偏好；这是可独立交付的日常缺口 |

因此选择让用户明确授权一组记忆在当前会话连续使用。参考 [Letta / MemGPT 的 Memory Blocks](https://www.letta.com/blog/memory-blocks/) 对受限上下文块和逐次编译模型输入的设计；本项目复用已有 Memory Store、原生选择器和 ConversationExecution，不引入第二套记忆服务或复制 SDK。参考只用于设计判断，未宣称具有 Letta 的自编辑记忆或后台学习能力。

## 可用行为

1. 在会话点击“选择记忆…”，原生预览确认后，默认仍只用于下一次发送。
2. 勾选“在当前会话连续使用这组记忆”，之后每次手动发送保留同一组有序 ID 和版本，界面持续显示标题／版本与作用范围。
3. 取消勾选后，当前选择只再用于下一次发送；“清除记忆”立即清除后续选择。已经接纳的请求及历史内容不会被撤回，历史回复中仍可能含先前记忆的信息。
4. 更换选择会关闭连续使用；原生选择器取消则保留原选择和开关。切换会话、离开会话页、页面禁用、归档或文档 session 重置会清除连续使用；重开窗口不恢复。
5. 版本过期会关闭连续使用并保留提示，需重新选择或清除才能发送；提交结果未知或其他提交失败则清除选择，保留草稿并查看持久历史，不自动重试。

这只消除连续对话中的重复选择。没有跨会话／跨重启偏好、后台自动提取、自动保存、全库语义召回、冲突解决或自动版本升级；不能保证模型遵循所给记忆。

## 实现与边界

- `WorkspaceClient.sendConversation` 仅在勾选时增加 `retainMemories: true`；未勾选的旧三字段请求保持不变。Native 严格接受可选布尔值，拒绝字符串、null、未知额外字段；空选择不能申请连续使用。
- `WorkspaceConversations.SendAsync` 继续验证同一文档、会话、选择 epoch 和精确引用；仅成功接纳且明确 opt-in 时保留授权，普通提交照常消耗。过期标记 NeedsReview，未知／其他发出后的失败消耗授权；预检期间被清除的选择不能发出。
- 该开关不进入 Runtime HTTP 请求。每轮仍由 `ConversationExecution.submit` 调用 `MemoryStore.snapshotForAsk` 校验全部 ID／版本／ACTIVE 状态并取得快照；没有部分使用、版本替换或缓存旧正文，输入预算也未放宽。
- 离开页面主动清除 Native 选择，已有 generation 与 selection epoch 隔离迟到结果。只保存临时引用及显示元数据，不写 localStorage、URL、日志或数据库。
- 生产变更限 React／Bridge／Native 选择生命周期与一条样式；没有 Java、schema、依赖、模型配置或服务修改。原无状态 Ask 行为保持原样。

## 共享模型验证的可行协调方式

检查 `ActiveModelManager` 可见 lease 是单 JVM 内的集合与 gate；它约束 Workspace 自己的准入，不能阻止 KAG 或其他客户端向共享 Ollama 发请求。现有 `ensureActive` 还可能触发模型验证探针，因此不能用一次真实请求作为无成本的“只读检测”。本仓库未找到双方实际遵循的资源协调协议。

可行前置是双方控制方共同认可的短时执行窗口：先确认各自没有在途推理、窗口内不会提交新任务，再在保留现有服务／模型配置的情况下取得当前 Workspace Ready／准入证据，仅执行少量合成输入；若不确定则停止准入，不切模型或重启服务。长期方案可以是两个项目都实际遵循的协调器；仅由 Workspace 创建文件锁、换端口或观察一次显存空闲都不足以提供隔离。

本轮只查明上述边界，没有建立或假设该窗口，也没有联系其他项目、暂停任务、读取个人配置或运行验证探针。未来协调需保留 KAG 的资源控制权；当前授权范围内继续完成独立功能，不把资源条件未核定描述成“模型不可用”。
