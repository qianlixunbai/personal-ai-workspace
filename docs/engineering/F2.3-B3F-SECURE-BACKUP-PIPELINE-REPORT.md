## 2. 直接加密的实际流水线

```text
显式停写声明 + 合成源库准入
  → REPEATABLE READ / SHARE 表锁 / Knowledge admission advisory lock
  → 固定 revision 文件只读句柄（Windows 禁写／禁删）及数据库／文件摘要核对
  → pg_export_snapshot()
  → pg_dump --format=custom --snapshot=… 的 stdout
  → database.dump ZIP entry + 锁定 Knowledge 文件 entries
  → 源文件／当前数据库／序列复查
  → 最后写 Manifest 与 BACKUP_COMPLETE 摘要 entry
  → 关闭快照连接／文件句柄、完成 ZIP 与 OpenPGP 末尾认证
  → force 密文 pending → 同目录 ATOMIC_MOVE → 最后原子发布外层完成凭据
```

复用 B3 的表／历史／任务准入、snapshot、Knowledge parser/representation/source digest、官方 PostgreSQL 工具，
及 B3E 的 BC 1.86 OpenPGP。**直接备份不生成磁盘明文 database.dump、ZIP 或 Knowledge 副本。**
ZIP 中仍有名为 `database.dump` 的 custom archive entry；它不是磁盘中间文件。
旧 B3 明文入口仍只接受原合成库范围，不能作为正式个人数据默认备份步骤；新入口也没有提前放开正式源库准入。

维护 CLI（交互终端读取恢复口令；私有源配置包含 sourceDatabase/sourceUsername/sourcePassword/knowledgeRoot/tools）：

```text
PortableEncryptedBackupCli backup <private-source-config.json> <new-encrypted-directory> --writers-stopped
PortableEncryptedBackupCli restore <encrypted-directory> <new-private-staging> <private-target-config.json> --trust-sql-source
PortableEncryptedBackupCli decrypt <encrypted-directory> <new-private-staging>
PortableEncryptedBackupCli cleanup-staging <explicit-operation-staging>
```

类的完整包名为 `io.github.qianlixunbai.workspace.backup.PortableEncryptedBackupCli`，使用现有 Java 21 runtime classpath。
恢复／导出／清理默认执行卷保护检查；只有合成维护场景可显式追加 `--synthetic-unencrypted-volume`。

pg_dump stdout 以 64 KiB 缓冲直接写 ZIP／加密流，无全量内存包或无界任务队列；OS pipe 与同步输出提供背压。
检查 PGDMP 签名、字节上限、退出码和 120 秒 deadline；stderr 丢弃，口令仅沿原私有配置／子进程环境合同传递，
不进入命令参数或报告。取消／超时／输出失败会终止并回收子进程，保留线程中断标志，不发布最终完成凭据。
数据库连接及 revision 句柄关闭失败同样阻止完成发布。未执行容量、压力或掉电持久性测试。

## 4. 恢复明文生命周期

恢复保持同一密文文件的禁写／禁删句柄：第一遍完整解密到 null sink，验证所有 chunk、末尾认证及 EOF；
第二遍重新解密并直接流式解包，再完成认证和内部 Manifest／内容验证。**不生成 bundle.zip 或 bundle.zip.pending。**
目标配置在上述步骤后才读取，pg_restore 和候选文件复制继续沿原 B3 新空库／ownership receipt／最小授权合同执行。
来源信任仍需独立声明，认证成功不代表发送者 SQL 可信。

必要明文仅落在本次新建私有 staging 的 `backup/`：一份 database.dump 与 Knowledge 文件。
恢复成功、目标配置失败、重复目标拒绝、认证／ZIP 校验失败的临时 backup 子树均确定清理；
清理前检查私有 owner/ACL、无链接、树深和条目上限，只删本次操作精确子树。
清理失败会报错并留下不含正文／私有摘要的 `PLAINTEXT_CLEANUP_REQUIRED`；成功留下 `PLAINTEXT_CLEANED`。

显式 `decrypt` 是保留明文导出的维护操作，成功时输出 `EXPLICIT_PLAINTEXT_EXPORT_RETAINED`；
它的调用者必须在读完后调用清理。集成流程已实际清理两份 v1/v2 导出。
恢复的 `candidate/knowledge` 是隔离恢复结果，成功后保留；失败候选、数据库及其证据也不自动删除。
因此文件复制期间仍可能短暂存在解包文件与候选文件两份，不宣称完全无明文。
进程被强杀／系统崩溃时不能保证 finally 执行；没有自动扫描旧目录，需对明确操作根执行 `cleanup-staging`。
该命令仅清理其 `backup/`，不删除候选、数据库、源文件或合法备份。
普通删除不代表 SSD 安全擦除，不保证 JVM 复制、分页、休眠或崩溃转储中没有明文。
